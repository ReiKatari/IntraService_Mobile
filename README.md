# IntraService Mobile

Нативное Android-приложение для выездных инженеров и исполнителей заявок **IntraService** (`https://intra.lantaservice.com`).

Построено на современном стеке (**Kotlin + Jetpack Compose + Material 3 + CameraX**) с акцентом на минимальный вес APK, плавные анимации, защищённое хранение учётных данных и надёжную работу на мобильных и Wi-Fi сетях.

- **Релизы и готовый APK**: [Releases (`IntraService Mobile 1.6.0`)](https://github.com/ReiKatari/IntraService_Mobile/releases/latest)

---

## Возможности (версия 1.6.0)

1. **Авторизация по логину или E-mail и строгая изоляция пользователя**
   - Без авторизации в приложении отображается только окно входа (с отображением текущей версии приложения и иконки).
   - Поддерживается вход как по обычному логину, так и по корпоративному адресу электронной почты (например, `p.stasyuk@lantaservice.com`) - с автоматическим определением логина через API и веб-форму IntraService.
   - Адрес сервера жёстко зафиксирован на `https://intra.lantaservice.com`.
   - При включённом тумблере «Запомнить меня» логин/e-mail и пароль шифруются через `AndroidKeyStore` (`AES-256-GCM`) и сохраняются в полях ввода даже после выхода из приложения, нажатия кнопки **«Выйти»**, перезапуска или ошибки сети (очистка выполняется только при выключении тумблера). После закрытия приложения при следующем запуске снова показывается экран входа.
   - Нажатие кнопки **«Выйти»** полностью очищает активную сессию и закрывает приложение.
   - Все запросы, вложение фотографий и смена статуса отправляются **строго от лица авторизованного пользователя**.

2. **Контроль разрешения местонахождения**
   - При запуске запрашивается разрешение геолокации (`ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`).
   - Если разрешение не выдано, отображается экран со статусом `Не выдано разрешение на местонахождение` и кнопкой повторного запроса (при блокировке системного диалога открываются настройки приложения).

3. **Два списка открытых заявок и автообновление**
   - В шапке экранов отображаются полные данные авторизованного исполнителя с адаптивной многострочной вёрсткой без обрезания текста (с учётом системных вырезов), поиск по номеру/названию/сервису, ручное обновление (`Pull-to-Refresh`) и единый формат дат `dd.MM.yyyy` и даты со временем `dd.MM.yyyy HH:mm`.
   - Вкладки со счётчиками:
     - **«В работе»** - открытые заявки на исполнителе, в истории которых ещё не было статуса «Починил».
     - **«Выполнено»** - открытые заявки, где статус «Починил» установлен сейчас или встречался в истории (`GET /api/tasklifetime`).
   - **Фоновое автообновление каждые 60 секунд** (пока экран активен) в списке и в карточке заявки без сброса несохранённых фото и комментария.

4. **Умная камера с подсказками и движок повышения чёткости фото**
   - Встроенная камера **CameraX** прямо в карточке заявки (`Сделать фото`) + поддержка выбора из галереи.
   - Живые индикаторы **Свет**, **Чёткость**, **Стабильно** (анализ яркости, бликов, вариации Лапласиана и смещения кадра в реальном времени), фонарик, фокус по нажатию, зум щипком и текстовые подсказки, когда лучше делать снимок.
   - Движок **PhotoEnhancerEngine** (автобаланс белого, локальное контрастирование `8x8` CLAHE-lite, сглаживание шума на ровных участках и многомасштабное повышение резкости яркости текста), а также экран предпросмотра **«Улучшено / Оригинал»** перед прикреплением.
   - Прикрепление через `POST /api/TaskFile` и сохранение в заявке через `PUT /api/task/{id}` с автоматическим переходом на вкладку **«Выполнено»**.
   - **Отложенная офлайн-отправка (`PendingOutbox`)**: если сервер IntraService временно недоступен, приложение фиксирует точную дату и время попытки (`dd.MM.yyyy HH:mm`) и надёжно сохраняет файлы, статус и комментарий локально; при изменении статуса или фото до отправки зафиксированные данные обновляются на новые, а при восстановлении связи изменения автоматически загружаются в Интру с зафиксированными датой и временем.
   - **Глубокая оптимизация производительности**: пул соединений OkHttp, кэширование справочника статусов и заявок, кэширование изображений в Coil, параллельная обработка пары «Оригинал / Улучшено» и оптимизированные Compose-модели без лишних перерисовок.

5. **Многомаршрутное подключение и устойчивый DNS**
   - 4-ступенчатый резолвер `IntraResilientDns`: системный DNS с приоритетом IPv4 -> прямой UDP порт 53 (`77.88.8.8`, `8.8.8.8`) -> прямой DoH JSON -> кэшированный / резервный IPv4 с полной проверкой TLS SNI `intra.lantaservice.com`.
   - Автоматический обход сбойного канала (`IntraConnectionManager`): при таймауте пробует не-VPN сети (`Wi-Fi`, `Cellular`) и прямое IPv4-соединение `HTTP/1.1` + `TLSv1.2`. При блокировке трафика не-обходным VPN (например, AdGuard с зарубежным выходным узлом) выводит подсказку и кнопку **«Открыть настройки VPN»**.

6. **Фоновая проверка и установка обновлений внутри приложения**
   - При запуске тихо проверяется последний релиз на GitHub (`api.github.com` с резервным переходом на веб-страницу релизов при rate-limit).
   - При выходе новой версии появляется диалог обновления с описанием изменений, прогрессом загрузки APK и запуском системного установщика.

## Установка готового APK на Android

1. Скачайте актуальный `.apk` из раздела [Releases](https://github.com/ReiKatari/IntraService_Mobile/releases/latest).
2. Откройте файл на телефоне (Android 8.0+ / API 26+) и при запросе разрешите установку приложений из этого источника.
3. **Важно при использовании VPN (AdGuard и т.п.)**: сервер `intra.lantaservice.com` может не отвечать через зарубежные VPN-выходы. В настройках VPN добавьте **IntraService Mobile** в список исключений (раздельное туннелирование), если сервер не открывается при включённом VPN.

## Сборка из исходников

### Требования
- **JDK 21** (или JDK 17+)
- **Android SDK** (`compileSdk = 36`, `minSdk = 26`, `targetSdk = 36`)
- **Gradle 8.13** (включён через `./gradlew` / `gradlew.bat`)

### Команды сборки и тестирования

1. Клонируйте репозиторий и создайте файл `local.properties` в корне с путём к вашему Android SDK:
   ```properties
   sdk.dir=C\:\\Users\\<USER>\\AppData\\Local\\Android\\Sdk
   ```
2. Запустите модульные тесты:
   ```bash
   ./gradlew testDebugUnitTest
   ```
3. Соберите debug или release APK (при отсутствии собственного `app/intra-release.jks` сборка `assembleRelease` автоматически подпишется debug-ключом):
   ```bash
   ./gradlew assembleRelease
   ```
   Готовый файл появится в `app/build/outputs/apk/release/app-release.apk`.

## Стек технологий

- **Kotlin 2.3.21** + Coroutines + Kotlinx Serialization
- **Jetpack Compose** (`1.11.1`) + **Material 3** (`1.4.0`) + **Navigation Compose** (`2.9.8`)
- **CameraX** (`1.6.1`: `camera-core`, `camera-camera2`, `camera-lifecycle`, `camera-view`)
- **Retrofit 3.0.0** + **OkHttp 4.12.0** + **Coil 2.7.0**
- **AndroidKeyStore AES-256-GCM** для хранения данных входа
